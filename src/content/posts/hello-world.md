## 为什么现在才开始写博客

其实"想写博客"这件事在我的 TODO 列表里躺了很久，久到我自己都不好意思看创建日期。拖延的理由五花八门，大致可以归纳成下面几条：

- **完美主义作祟**：总觉得要等下面这些都齐活了才能上线：
  - 技术选型想清楚
  - 设计稿画完
  - 内容库存备够
- **三分钟热度**：好几次动手写了模板，第二天就去忙别的事情，主题分支在仓库里吃了好几个月的灰；
- **不知道写给谁看**：一直纠结这博客到底是写给自己看的备忘录，还是想认真经营的公开内容。

直到最近，我想通了一件事：*与其等一个完美的时机，不如先让它跑起来，再在跑的过程中慢慢打磨*。所以这篇文章的存在本身，就是"==完成比完美更重要=="这句话的一个小小注脚。

## 这个博客是怎么搭起来的

好啦，重头戏来了，估计也是很多同类型博客读者最感兴趣的部分：**这玩意儿到底是拿什么搭的？**

### 技术栈一览

整个站点基于以下这套组合拳：

- **框架**：[Astro](https://astro.build/)，静态优先、按需注水，博客这种内容型网站简直是量身定做；
- **主题**：在一个开源主题的基础上做了不少个性化魔改；
- **部署**：托管在 Vercel 上，配合 GitHub Actions 做 CI/CD；
- **域名 & CDN**：Cloudflare 一条龙搞定；
- **写作工具**：Markdown + VS Code + 一堆稀奇古怪的插件。

#### 项目结构

项目的目录结构大致长这样：

```bash
.
├── src
│   ├── content
│   │   └── posts/          # 所有文章都在这里，纯 Markdown
│   ├── components/
│   ├── layouts/
│   └── pages/
├── public/
├── astro.config.mjs
└── package.json
```

安装依赖、跑起开发环境是这样的：

```bash
# 克隆仓库
git clone https://github.com/your-name/your-blog.git
cd your-blog

# 安装依赖（强烈建议用 pnpm）
pnpm install

# 启动本地开发服务器
pnpm dev
```

跑起来之后，打开 `http://localhost:4321` 就能看到本地预览了。顺带一提，如果想随时终止开发服务器，直接按 <kbd>Ctrl</kbd> + <kbd>C</kbd> 就行。

### 技术选型的取舍

选框架这件事，我其实纠结了挺久，简单列一下当时对比过的几个方案：

| 方案 | 优点 | 缺点 | 最终选择 |
| :--- | :--- | ---: | :---: |
| Hugo | 编译速度快到离谱 | Go 模板语法不太顺手 | ❌ |
| Hexo | 生态成熟，插件多 | 更新略缓慢 | ❌ |
| VitePress | 对文档类站点友好 | 更偏文档而非博客 | ❌ |
| **Astro** | 组件写法灵活、性能优秀 | 生态相对年轻 | ✅ |

> 💡 **小提示**：如果你也在纠结选型，我的建议是——不要在这一步纠结太久。框架只是工具，能让你持续写下去的才是好框架。

除此之外，还有一些我个人比较看重、但不一定适合所有人的取舍：

1. 放弃了带评论区的方案，~~主要是懒得管理垃圾评论~~，更希望大家用邮件或者社交平台跟我交流；
2. 没有做多语言，至少现阶段没有这个精力；
3. 坚持纯 Markdown 写作，不想被所见即所得编辑器绑架。
